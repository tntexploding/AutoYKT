# 课前回放与正式测试

两小时持续测试使用[统一课堂入口](class-session.md)，原有单题回放与现场标定方法如下。

## 已有题图的完整回放

先安装依赖并在私有配置中设置 Flash 密钥和截图标定。个人配置、题图、模板和结果放在仓库之外。

```powershell
autoykt check
autoykt rehearse --profile <profile-id> --image <question-1.png> --image <question-2.png>
```

`--image` 可重复指定，坐标必须对应图片实际尺寸。`--output` 如指定，须为尚不存在的新目录，防止旧的去重状态污染本轮结果。

回放先进入无题等待，再把每张源图转为内存中的未选中状态。题干、题型和选项布局来自源图；题型识别、OCR、模型请求、投票、按钮定位、选中检查、提交检查和下一题去重复用正式流程。启动时先加载 OCR，启动耗时单独记录，不计入单题预算。

题目文字会按私有配置发送给 Flash。当前默认先并发 3 次，不足或平票时最多补问到 5 次；至少两份有效回复、获胜至少两票。若当前批次胜者已经不能被剩余回复追平或超过，立即取消慢请求。多选以完整选项集合计票，不拼接不同回答中的字母。截断、空值、低置信度回答不计票。

输出包括 `report.json`、各题的虚拟前后画面以及正式状态机的操作报告。顶层报告明确标注 `simulation: true`，真实桌面点击和网站提交均为 0。内部操作报告的 `kind: live` 表示执行了允许输入的状态机分支，不能作为真实网站提交证据；输入后端仍是虚拟鼠标。

通过条件是无题时不输入、每题完成一次选择和模拟提交、通过完成模板确认、在下题出现后重新识别，以及在完成画面停留时不重复答题。模型答案是否正确需要课程标准答案独立核对，得票率不是正确率。

## 下次真实课堂

1. 在课前启动并完成 OCR 加载，保留几道新题供人工监控。使用 `autoykt windows` 获取目标窗口，再按 [正式页面操作标定](formal-page-operations.md) 重新采集实际窗口内的区域。聊天里缩小后的题图坐标不能直接当作真实窗口坐标。
2. 标定题型触发、页面身份、每个字母模板、蓝色/灰色状态及“已完成”反馈。单选和多选分别配置题型触发模板；若圆形和方形按钮的字母相同，可复用中央字母模板并标定 `button_colors.button_size`。字母数量和位置由当页检测结果确定。
3. 标定真实提交目标。只有现场确认单选“点击即提交”后，才设置 `submit_on_select: true`；多选必须配置 `submit_target`。按实际页面补齐过期、异常或需要人工处理的状态模板。
4. 在私有配置中启用相应 profile，运行 `autoykt check --live --profile <profile-id>`。该命令不截图、不点击，也不会调用模型，只列出缺失配置。
5. 保持人工监控，先使用 `autoykt run --profile <profile-id> --once --dry-run` 检查新题的答案与定位。正式测试时设定 `runtime.dry_run: false`、`answering.auto_apply: true`，使用 `autoykt run --profile <profile-id> --once` 完成一题并查看报告；确认选中状态和真实完成反馈后再去掉 `--once`。

推荐当前一分钟题目采用总预算 50 秒、OCR/知识上下文 5 秒、模型回答至多 35 秒，并保留选择和提交确认时间。`recovery.maximum_attempts: 1` 配合模型内部 5 次采样，避免整轮再次重试导致请求数翻倍。网络、题目依赖图片或课程特定知识、教师提前结束等情况仍可能导致无答案；最终平票或提交不明确时保留证据并交给现场监控人员。

图像回放只验证本地流程。真实窗口绑定、倒计时状态及服务器接受提交，必须通过真实新题验收。
